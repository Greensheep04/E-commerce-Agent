# 命令说明

所有命令从仓库根目录执行。运行要求与配置字段见[环境说明](环境说明.md)。下面的账号、UUID和文件名示例需要替换为自己的配置。

## 安装与初始化

复制配置后填写数据库和模型凭据，准备缓存目录并安装主环境：

```bash
cp .env.example .env
mkdir -p .scratch/uv-cache .scratch/runtime .local/auth
UV_CACHE_DIR=.scratch/uv-cache TMPDIR=.scratch/runtime uv sync --frozen --extra dev
```

使用本地PostgreSQL时，将可执行文件目录替换为自己的安装路径：

```bash
export SHOP_POSTGRES_BIN=/path/to/postgresql/bin
bash scripts/postgres.sh init
bash scripts/postgres.sh start
.venv/bin/alembic upgrade head
.venv/bin/python scripts/manage.py init-admin
```

`init-admin`创建管理员账号，并将密码保存到`.local/auth/admin.password`，会话密钥保存到`.local/auth/session.key`。账号与密码文件已存在时，保留原配置。

构建前端并启动Shop：

```bash
npm --prefix frontend ci
npm --prefix frontend run build
bash scripts/run_api.sh
```

网页入口为`http://127.0.0.1:8000/harness/`，管理入口为`http://127.0.0.1:8000/admin`。通过管理页面登记素材来源和管理文件；业务页面选择宣传页面、客服、考核或数据中台。

## 素材与客服资料

导入固定素材样例，配置模型凭据后建立索引：

```bash
HF_HOME=.scratch/huggingface .venv/bin/python scripts/import_fashion.py
.venv/bin/python scripts/index_materials.py
```

索引命令调用图片描述和embedding模型。上传自己的素材可使用管理页面，或认证后的`POST /api/assets`；表单字段为`source_id`、`source_revision`、`record_id`、`title`、`kind`和`file`，`kind`支持`text`、`image`与`video`。

导入AdventureWorks历史订单并建立客服演示账号：

```bash
.venv/bin/python scripts/import_orders.py --create-customers
```

演示账号为`customer-11091`和`customer-11176`，密码文件保存在`.local/auth/`。客服页面为`/harness/?workspace=customer`，商品资料查询使用已经建立的素材索引。

## 销售考核与自媒体

准备员工及目标来源并导入：

```bash
.venv/bin/python -m scripts.prepare_assessment_data
.venv/bin/python -m scripts.assessment import-employees
```

需要演示账号时执行：

```bash
.venv/bin/python -m scripts.setup_assessment_sample
```

账号权限与密码文件清单保存在`.local/assessment/auth/sample-access.json`。管理已有业务账号、创建任务、执行与导出报告的参数见：

```bash
.venv/bin/python -m scripts.assessment --help
.venv/bin/python -m scripts.poster --help
```

Poster的`prepare`接收Harness任务编号，`direct`接收关键词及素材版本编号，`--agents module:function`登记业务角色。执行完整海报流程需要登记相应角色；角色不足时结果说明缺失项。

## MCP与目标操作

安装Hub环境：

```bash
UV_CACHE_DIR=.scratch/uv-cache TMPDIR=.scratch/runtime uv sync --project agent-hub --frozen
```

根据[Agent Hub](../../agent-hub/README.md)准备受保护的身份配置。外部MCP客户端启动命令为：

```bash
agent-hub/.venv/bin/python -m agent_hub --config /absolute/path/to/hub.json
```

目标操作使用[Agent Cluster](../../agent-cluster/README.md)中的集群和CLI配置。将`SHOP_CLUSTER_CONFIG_FILE`设置为集群配置路径后启动Shop：

```bash
SHOP_CLUSTER_CONFIG_FILE=.local/cluster/config.json bash scripts/run_api.sh
```

CLI配置和目标输入分别保存在`.local/cluster/client.json`与`.local/cluster/goal.json`。目标声明允许操作、完成条件及预算；使用以下命令创建、启动和控制目标：

```bash
.venv/bin/agent-cluster --config .local/cluster/client.json goals create --file .local/cluster/goal.json
.venv/bin/agent-cluster --config .local/cluster/client.json goals start GOAL_ID --event-id manual-001
.venv/bin/agent-cluster --config .local/cluster/client.json goals show GOAL_ID
.venv/bin/agent-cluster --config .local/cluster/client.json goals pause GOAL_ID
.venv/bin/agent-cluster --config .local/cluster/client.json goals resume GOAL_ID
.venv/bin/agent-cluster --config .local/cluster/client.json goals cancel GOAL_ID
.venv/bin/agent-cluster --config .local/cluster/client.json runs show RUN_ID
.venv/bin/agent-cluster --config .local/cluster/client.json schedules create --goal-id GOAL_ID --interval-seconds 3600
```

## 独立数据中台

安装Python 3.14独立环境，并初始化本地数据中台数据库：

```bash
UV_CACHE_DIR=.scratch/uv-cache TMPDIR=.scratch/runtime uv sync --project data-center --frozen --extra dev
data-center/.venv/bin/python scripts/bootstrap_data_center.py --output .local/data-center/schema.json
```

数据库初始化脚本用于本项目本机55432端口、`shop`数据库管理账号的部署，创建`shop_data_center`、reader/writer角色、pgvector和RLS。使用其他数据库地址时需要按该环境执行相同的数据库及权限初始化。

身份文件`.local/data-center/identities.json`使用以下格式；`actor_id`取真实登录响应的`id`，密码文件使用`0600`权限：

```json
{
  "actors": {
    "admin": {
      "actor_id": "authenticated-user-id",
      "username": "admin",
      "password_file": ".local/auth/admin.password"
    }
  }
}
```

为每个需要执行目标的账号登记一项。准备Hub、集群和服务身份文件：

```bash
.venv/bin/python scripts/prepare_data_center_runtime.py --identities .local/data-center/identities.json --output .local/data-center/runtime --shop-url http://127.0.0.1:8002
```

程序生成共享服务身份文件及每个账号的Hub配置。生成的集群配置中`autorun=false`，`data_center_autorun=true`；根据需要设置自动执行，来源监听目标还需通过`install_data_center_watch.py`登记。

下载Docling模型并准备Tokenizer缓存，扫描PDF还需要在系统中安装Tesseract及对应语言资料：

```bash
data-center/.venv/bin/docling-tools models download --output-dir .local/data-center/models/docling
TIKTOKEN_CACHE_DIR=.local/data-center/tiktoken data-center/.venv/bin/python -c 'import tiktoken; tiktoken.get_encoding("cl100k_base")'
```

在一个终端启动数据服务，随后在另一个终端启动Shop；服务地址需要与生成的Hub配置一致：

```bash
TIKTOKEN_CACHE_DIR=.local/data-center/tiktoken DATA_CENTER_GRAPH_ENABLED=false DATA_CENTER_SHOP_URL=http://127.0.0.1:8002 uv run --project data-center --no-sync uvicorn data_center.api:create_app --factory --host 127.0.0.1 --port 8100
```

```bash
SHOP_DATA_CENTER_URL=http://127.0.0.1:8100 SHOP_CLUSTER_CONFIG_FILE=.local/data-center/runtime/cluster.json uv run --no-sync uvicorn shop.app:app --host 127.0.0.1 --port 8002
```

两个服务均提供`/health`。启用后通过`http://127.0.0.1:8002/harness/?workspace=data-center`使用数据中台。

来源登记输入符合`SourceRegistration`，授权输入符合`GrantRegistration`，文档输入符合`DocumentIngest`。管理员登记自己的文档原件、来源及账号权限后，使用CLI导入资料和问答：

```bash
data-center/.venv/bin/data-center --username admin --password-file .local/auth/admin.password --request-id REQUEST_ID register-source .local/data-center/source.json
data-center/.venv/bin/data-center --username admin --password-file .local/auth/admin.password --request-id REQUEST_ID set-grant .local/data-center/grant.json
data-center/.venv/bin/data-center --username admin --password-file .local/auth/admin.password --request-id REQUEST_ID invoke ingest --input .local/data-center/ingest.json
data-center/.venv/bin/data-center --username admin --password-file .local/auth/admin.password --request-id REQUEST_ID ask "资料中如何配置接口？" --source-id SOURCE_ID --retrieval-mode hybrid
data-center/.venv/bin/data-center --username admin --password-file .local/auth/admin.password --request-id REQUEST_ID show TASK_ID
data-center/.venv/bin/data-center --username admin --password-file .local/auth/admin.password --request-id REQUEST_ID export TASK_ID --format markdown --output .local/data-center/answer.md
```

每个独立操作使用自己的UUID作为`REQUEST_ID`；重复同一操作和内容时使用原UUID。`ask`返回任务编号，通过`show`查询，`run`继续任务，`cancel`取消任务。`invoke OPERATION --input FILE.json`调用公共操作，完整字段见[接口说明](接口说明.md)。

同步与日程参数见：

```bash
.venv/bin/python scripts/install_data_center_watch.py --help
data-center/.venv/bin/data-center --help
```

## 查询用量与停止服务

以下命令读取记录，不调用模型：

```bash
.venv/bin/python scripts/report_harness_usage.py
.venv/bin/python scripts/report_customer_usage.py
.venv/bin/python scripts/report_customer_turn.py TURN_ID
.venv/bin/python scripts/report_data_center_usage.py --help
bash scripts/postgres.sh status
```

在服务终端使用Ctrl+C停止进程；确认任务不再使用数据库后执行`bash scripts/postgres.sh stop`。

## 源码发布包

导出用于首次公开提交的源码包：

```bash
.venv/bin/python scripts/export_public_source.py --output .scratch/releases/project-shop-source.tar.gz
```

发布包保留代码、依赖、迁移、配置示例和本目录使用说明。包内文件可用于建立新的GitHub仓库初始提交；上传与部署时自行配置账号、模型凭据及数据。
